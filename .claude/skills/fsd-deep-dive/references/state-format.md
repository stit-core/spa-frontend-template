# Формат заметки `state/<kind>.md`

Память скилла — рабочее состояние знания об FSD-артефакте. **Не журнал**.

Лежит рядом со скиллом (`.claude/skills/fsd-deep-dive/state/`) и
**коммитится** — общая проектная память между сессиями и архитекторами.
Не часть артефактного канона `docs/fsd/` (туда уходят зафиксированные
решения по слоям). Forward-only: только текущее открытое, не «было/стало»,
без дат сессий. Это держит `git log` чистым — коммиты в state маленькие и
тематические («закрыл blocker про границу widget/page»), а не нарратив.

FSD-карта — 8 фиксированных singleton-артефактов (`app`, `pages`, `widgets`,
`features`, `entities`, `shared-ui`, `shared-api`, `shared-lib`), поэтому путь
плоский: `state/<kind>.md` (без вложений).

## Шаблон

```markdown
---
kind: features
ref: docs/fsd/features.md
---

## Открытые вопросы
- `auth` и `session` — фича или подъём в entities? (**blocker**)
- Нужен ли отдельный widget под фильтры, или это часть page? — ждём ≥2 page-референса.

## Доменные решения
- `todos` остаётся page-локальным слайсом сознательно — переиспользования
  пока нет, выносить в widget рано (pages-first).

## Что копать дальше
- После решения по auth — синхронизировать `entities.md § Карта entities`
  и `shared-api.md § Mock-сущности`.
```

## Frontmatter

| ключ | значение | назначение |
|---|---|---|
| `kind` | один из 8 FSD-kinds | подсказка |
| `ref` | путь к артефакту от корня репо | удобная ссылка в редакторе |

## Секции

Все три опциональны.

### `## Открытые вопросы`

Список незакрытых смысловых вопросов. Каждый — одна строка.

- Префикс `**blocker:**` ИЛИ суффикс `(**blocker**)` — блокирует stable.
- Закрытый вопрос **удаляется** (не зачёркивается). Пусто → удалить секцию.
- Falsifiable формулировка. Хорошо: «`session` нужна как отдельная entity,
  если auth и profile делят её состояние?». Плохо: «разобраться с auth».
- **Cross-kind blocker** (фича ссылается на сущность, которой нет в
  `entities.md`; widget с 1 page-референсом) — частый случай. Помечать в state
  того kind'а, который недополучил.

### `## Доменные решения`

Список неочевидных смысловых решений, не влезших в артефакт по форме.

- Одна строка списка = одно решение.
- Форма: «<что выбрано> — <почему>». Без «было/стало», без дат.
- Если решение уже растворилось в самом артефакте (попало в текст таблицы,
  в `Architecture notes`) — удалить отсюда.

### `## Что копать дальше`

Список локальных «следующих шагов».

- Не путать с открытыми вопросами: шаг — задача, вопрос — неясный смысл.
- При выполнении — удалить строку. Пусто → удалить секцию.

## Правила жизненного цикла

- **Создаётся** только когда есть что записать.
- **Перезаписывается** свободно.
- **Удаляется**:
  - Все три секции пустые → удалить файл целиком.
  - Артефакт удалён (редкий кейс — артефакты singleton'ы) → удалить файл.
  - Артефакт промоутнут в `stable` без blocker'ов — заметка может остаться
    только если в ней непустые `## Доменные решения`.

## Что НЕ хранить

- Историю изменений (это `git log`).
- Журнал сессий «над чем работали такого-то числа».
- Дубликаты содержимого артефакта (имена слайсов, маппинги — это в самом файле).
- Подсказки от модели «обычно фронт нарезают так-то» — это не решение
  архитектора, не пишем.
- Сырьё `../docs/projects/<slug>/`, из которого мапили, — после разбора
  артефакт его поглотил.

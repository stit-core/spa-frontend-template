# Три режима ведения сеанса

`fsd-deep-dive` поддерживает три явно различающихся сценария входа. Скилл
выбирает режим по тому, что есть в соседнем `../docs/projects/<slug>/`.

## A. С аналитикой

**Сигнал**: в `../docs/projects/<slug>/interface/situation.md` есть ситуации,
в `../docs/projects/<slug>/domains/` есть сущности.

### Шаги

1. Прочитать `docs/fsd/README.md` § Слои — освежить контракт.
2. Прочитать аналитику папки проекта: `interface/situation.md`,
   `interface/zone.md`, `interface/data-items.md`, `domains/`,
   `screens/screens/`, `screens/blocks/`.
3. По слою (порядок inside-out из SKILL.md) мапить напрямую: ситуация →
   feature, сущность домена/data-item → entity, экран → page, повторяемый
   блок → widget (только при ≥2 page-референса).
4. Каждый кандидат — через волну вопросов (3–5), подтвердить / отбросить /
   переименовать. Не выдумывать слайсы, которых нет в источнике.
5. Открытые места — `state/<kind>.md` (формат — `references/state-format.md`).

## B. С эскизом

**Сигнал**: аналитики `../docs/projects/<slug>/` нет, но юзер принёс набросок
экранов / сценариев / описание UI.

### Шаги

1. Прочитать материал внимательно.
2. Извлечь кандидатов на слайсы и привязать к слоям (сценарий действия →
   feature, данные → entity, маршрут → page, повторяемый блок → widget).
3. Показать план через чат и подтвердить волной `AskUserQuestion`.
4. Завести/обновить артефакты как драфты. Дыры по обязательным секциям —
   `**blocker**` в `state/<kind>.md`.

### Что НЕ делать в режиме B

- Не объявлять извлечённое «зафиксированным» — это кандидаты до подтверждения.
- Не выдумывать `Generates` по эскизу — это контракт de-template, архитектор
  обдумывает его явно.
- Не изобретать продуктовые/UX-формулировки — это работа авторов
  `../docs/projects/<slug>/`.

## C. С нуля

**Сигнал**: ни аналитики, ни эскиза.

### Шаги

1. Задать базовые вопросы про сценарии и данные (волна 3–5 вопросов).
2. Из ответов — минимальный набор слайсов, остальное в `state/<kind>.md` как
   «что копать дальше».
3. Предупредить юзера: без `../docs/projects/<slug>/` проектируем налегке,
   stable требует возврата к аналитике.

## Каскады удаления

Слой удаляется не в одиночку:

- удалить **entity** → убрать её из `features.md`, `shared-api.md § Mock-сущности`,
  из всех `pages`/`widgets`, что её использовали;
- удалить **feature** → убрать из `pages.md`/`widgets.md`, где она композилась;
- удалить **widget** → вернуть его блоки в page-слайс (pages-first);
- осиротевшие маппинги на `../docs/projects/<slug>/` — снять.

После каскада — прогнать `references/draft-stable.md § Cross-kind` по
затронутым артефактам.

## Стиль вопросов

- Волна — 3–5 вопросов, не 10. Дизайн-решения — через `AskUserQuestion`.
- Имена слайсов — по сценарию из `situation.md`, не аббревиатуры от себя.
- Не предлагать «оптимизации» структуры FSD сверх того, что диктует источник.
- Не закрывать сессию без чек-листа `references/draft-stable.md` хотя бы по
  одному правленому артефакту.
